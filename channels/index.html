The pipeline every channel runs on

Plan, select, build, gate, post. Every episode on every channel goes through these five stages. The gate is the load-bearing one — that's why it carries the only warm colour in the diagram.

Plan
Brief against the audio, not before
Select
5 queries per need, vs-hero rank
Build
NEVER rules name their beat
Gate
Cosine + ask.py vision
Post
Copy, thumb, pin, queue

What the gate actually measures

The gate runs ResNet50 cosine similarity at three frame positions per scene, then asks a vision model for a modern/anachronism check. The pass/fail criterion is calibrated against the reverse-engineered luxury episode:

Scenet = 0%t = 50%t = 98%
s1_establish0.325 / 0.3170.324 / 0.3160.329 / 0.320
s2_deepen0.335 / 0.3270.353 / 0.3460.369 / 0.362
s3_exit0.231 / 0.2300.228 / 0.2260.211 / 0.213

The numbers are vs-seed / vs-hero. The third scene has the lowest scores and that is correct — a character walking away should diverge from the reference. The gate flags catastrophic divergence, not stylistic movement.

The six rules the pipeline enforces

Each rule closes one class of failure that cost real time or money. Every rule is documented, fileable, and automatic — not convention.

  1. Narrate first, brief against the audio. Estimated beats never match the TTS pauses. Plan after the audio, not before.
  2. Five queries per need. Identical queries put the same 50 jpgs in every folder; the selector dedups globally, so half the needs see nothing.
  3. Every NEVER names its beat. "No Kanao" rejected the very need whose line is "Then he met Kanao." Constraints are per-beat, not global.
  4. UNPARSEABLE means transport, not model failure. A timeout reads as a model fault unless the selector logs transport separately.
  5. Pixel review at full 1080×1920. Six frames passed at 640px and failed at full resolution. Confirm by opening the source PNG.
  6. Every claim matches the source verbatim. Two claims dropped from Musashi for being unsourced; one added to Speedmaster because it was sourced.
