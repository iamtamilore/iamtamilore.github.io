2. The blueprint (workflow that the channels all run on)

This is the workflow as it exists today, reverse-engineered from _LESSONS_HARD_WON.md, the brief.json structure, the _archive/reels_pipeline.sh shell, and the niche_config.json per-channel config.

2.1 Inputs

  • niche_config.json per channel (the niche rules)
  • A Wikipedia article URL (the source of every claim)
  • A beats.json (the audio timing, generated by the narrator TTS)
  • A subject pick (from the channel's subject catalog with measured lift ratios)

2.2 The five-stage pipeline

The shell in _archive/reels_pipeline.sh is the seed. The current Zenpai pipeline runs the same five stages:

  1. Plan — plan_choreography.py reads the audio (the beats) and writes brief.json (what the shots must cover). HARD RULE #1: the brief is written AGAINST the audio, not before it. Estimate N beats, hand-write N t values, the TTS pauses somewhere you did not predict — the builder reads the audio, not the brief. Tengen 2: brief 19 needs, audio 21 beats. Tengen 3: brief 19 needs, audio 17 beats, still broken.
  2. Select — select_frames.py fetches the source frames from the Wikipedia article for each beat, ranks them by vs_hero similarity, and writes shots.json. HARD RULE #2: per-need queries are mandatory. Identical queries across needs put the same 50 jpgs in every folder. The selector dedups globally, so needs 7-16 silently get nothing and the build cycles a few stills across all 16 shots. Five queries per need, character name first, plus a per-need verb.
  3. Build — build_.py calls kie.ai (Seedance for video, Flux-2 / GPT-Image-2 for images) and assembles EP_.mp4. HARD RULE #3: NEVER rules must name the beat they apply to. "no Kanao" rejected all 12 candidates for the need whose line is "Then he met Kanao." "no romance" rejected all 12 for the need whose line is "He fell in love with her." Both were blanket rules applied where the forbidden thing WAS the subject. Every NEVER names its beat. Hard character constraints stay absolute.
  4. Gate — qa_selector.py + apply_gates.py run ResNet50 cosine similarity vs-seed and vs-hero at three frame positions (t=0%, t=50%, t=98%), then call ask.py for vision-based verification. HARD RULE #4: "UNPARSEABLE response" from the selector means TRANSPORT, not model failure. Raw response was 361 bytes: gateway diagnostics plus [image] cN: embedded lines, then nothing. urlopen died before the response. select_frames.py discards stderr, so a timeout reads as a model fault. A 12-image vision call measured 101s against a 120s ceiling. HARD RULE #5: pixel review must be at full 1080x1920. Six frames passed the selector at 640px and failed human review at full resolution: watermark plate, second character, English speech bubbles, two pre-injury combat poses, and one frame with Tengen not in it at all. Confirm any "wrong character" call by opening the source PNG. Record rejections in sourced//overrides.json, never in verdicts.json.
  5. Post — POSTING/post.py queues the video, copy, thumbnail, and pinned comment to YouTube + TikTok + IG + FB via the channel's social MCPs. Writes EP__POSTED.txt and updates the channel's niche_config.json with the per-episode QA + view-history line.

2.3 The QA gate that actually runs

The gate that runs on every frame in every batch — qa_selector.py (ResNet50 cosine similarity, threshold M16.8–16.9 calibrated on a reference bank held out from the active training run). Calibrated against p1_flooded_street/qa.json from the reverse-engineered luxury episode:

Scenef00f50f98
------------
s1_establishvs-seed 0.325 vs-hero 0.3170.324 / 0.3160.329 / 0.320
s2_deepen0.335 / 0.3270.353 / 0.3460.369 / 0.362
s3_exit0.231 / 0.2300.228 / 0.2260.211 / 0.213

The gate's pass/fail criterion is: both vs-seed and vs-hero stay within the calibrated band for the scene type. Catastrophic divergence triggers an automatic regenerate. Stylistic drift within tolerance does not. The third scene has the lowest scores — that's correct: a character walking away SHOULD diverge from the reference. The gate is calibrated to flag catastrophic divergence, not stylistic movement.

2.4 What lives in `/mnt/2tb` vs the repo

/mnt/2b is the source of truth. ~/repos/zenpai-pipeline is a mirror; sync-zenpai-docs.sh copies the pipeline scripts from /mnt/2b into the repo on a cron every 30 minutes, then commits. Editing the repo directly is silently undone.** Change the script on /mnt/2tb and let the sync mirror it, or change both. (From luxury_archive/CONTEXT.md`.)
