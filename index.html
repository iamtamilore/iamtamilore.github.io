01 The question under all of it

Four things run through everything below: applying software architecture principles to AI systems, evaluating them for completeness and admissibility, critiquing model quality and evaluation design, and critiquing the infrastructure they deploy onto. Every model has a threshold, and where you set it is a business decision, not a technical one. A misrouted support ticket costs someone ten minutes. A line missed in a patient's history costs a great deal more. Every system below is a different answer to the same question: which error can we afford?

03 Before this

Where the constraints came from

  • Huawei two summers, Globacom network
    400 million daily call records, which are 400 million bills real people pay. I designed and tested the API layer for a cloud integration with a bank's customer care line, and tested every interface with curl before it went near a voice prompt. When authentication fails, that call does not retry silently and does not dead-end. It transfers to a person. I also worked with the solutions architect on the data migration, and with the test team designed over 440 acceptance test cases. 04 How I work

Method first

Establish the baseline before training anything. Name the error you can afford before choosing a threshold. Freeze the preprocessing with the model so training and serving cannot drift apart. Version every artefact so a bad deploy can be rolled back rather than diagnosed. State what breaks, in writing, next to what works.

Then the tools

Python and SQL. TensorFlow and Keras, scikit-learn, pandas, Matplotlib. RAG pipelines, vector search with pgvector and FAISS, LangGraph. PostgreSQL, Hadoop HDFS, HBase. Docker and Kubernetes, FastAPI, Flask. GDPR data cataloguing, lineage and UAT design. Linux, day to day.
