Workflow Blueprint

The eight-stage build behind every episode that ships on the channels, the gates that can refuse one, and six hard-won rules, one per failure that cost real time or money, that the pipeline enforces automatically. The proof is in the gates's actual behaviour, not in this write-up.

The nine stages

1. Plan → 2. Source → 3. Prefilter → 4. Rotcheck → 5. Select → 6. Crop → 7. Verify → 8. Build → 9. Post

Plan and Post sit around the eight-stage build that the driver runs. Every episode that ships on the channels goes through these nine steps in this order. The order is not a preference: rotation correction after selection cannot converge, so it has to happen first. Each step has its own scripts, its own inputs and its own failure modes. The rules at the bottom are the ones that were learned by getting a step wrong, and they are enforced automatically, not by convention.

Stage 1, Plan

Inputs

The source article (the source of every claim), the narration audio (voice.wav, words.json, beats.json), and the subject pick from the channel's subject_catalog.json.

Scripts

gate_brief_pile.py, gate_beat_alignment.py, gate_claims.py

What it does

Writes brief.json: which shots must cover which beats, and the source queries each shot need will use. Three gates run before the first paid call. The brief pile gate refuses a brief that has drifted from the batch, the beat alignment gate refuses a brief whose shot needs do not match the narration, and the claims gate refuses a claim the source does not state.

Failure mode

Hand-writing N beats when the TTS produces N±2. The builder then rescales every shot to fit, and the pictures drift ahead of the captions until they are seconds out of place.

Hard rule

Narrate first, then write the brief. The brief must be written AGAINST the audio, not before it. Estimate N beats, hand-write N t values, the TTS pauses somewhere you did not predict. The builder reads the audio, not the brief. (Tengen 2: brief 19, audio 21. Tengen 3: brief 19, audio 17, both broken until brief was rewritten from the actual audio.)

Inputs: subject_catalog.json, beats.json, source article   Output: brief.json

Stage 2, Source

Inputs

brief.json, and the source queries each shot need carries.

Script

ask.py source

What it does

Fetches candidate images for each shot need, one folder per need, using that need's own queries. This is the only paid stage in the front half of the build, which is why the gates run before it and not after.

Failure mode

Generic queries that produce the same 50 jpgs for every need. The selector dedups globally, so needs 7 to 16 silently get nothing and the build cycles a few stills across all 16 shots.

Hard rule

Five queries per need, character name first, plus a per-need verb. Identical queries across needs put the same 50 jpgs in every folder. The selector dedups globally, so needs 7 to 16 silently get nothing and the build cycles a few stills across all 16 shots. (EP_GOJO rebuild, 2026-10-22, ~$1.50 wasted before this rule.)

Inputs: brief.json   Output: sourced candidates, one folder per shot need

Stage 3, Prefilter

Inputs

The sourced candidates.

Script

prefilter.py

What it does

A geometry gate over the candidates. Arithmetic only, no model. A candidate is rejected when no acceptable 1080x1920 frame can come out of it. It runs twice: once on the raw candidates, and again after the rotation check has corrected the shortlist.

Failure mode

The first rule was a height floor, which assumed every usable candidate was portrait. A landscape frame of the right character came back from a raw fetch and was rejected as too small before the selector ever saw it. The crop was never the problem: the crop already takes the largest 9:16 rectangle that fits, and a landscape image has more width to work with than a portrait one.

Hard rule

Pixel maths never goes to a model. The threshold on the short side is a number in the script, not a sentence in a prompt. (EP_GIYU need 6, five source rounds and about 200 candidates, one good frame lost to a height floor.)

Inputs: sourced candidates   Output: the candidate set the selector is allowed to judge

Stage 4, Rotcheck

Inputs

The prefiltered candidates, then the cropped frames at the end of the build.

Script

rotcheck.py

What it does

A forced-choice rotation check. The image is rendered at 0, 90, 180 and 270 degrees into a labelled 2x2 sheet and the model picks the upright panel. It runs on the shortlist before selection, and again on the final cropped frames.

Failure mode

Two rotated frames shipped in a finished episode. The selector scored both as upright while describing their content correctly, and the EXIF orientation was 1 on both, so neither defence fired. Vision encoders are trained with rotation augmentation, so a rotated landscape still looks like a landscape to the embedding.

Hard rule

Ask which of these four is upright, never is this upright. The comparison has to look at the same content four ways, so the answer cannot come from the caption. Panel A is always the original pixels, so "A" means upright and anything else names the rotation.

Inputs: candidate images   Output: rotation.json, with the correction applied in place

Stage 5, Select

Inputs

brief.json and the prefiltered candidates.

Script

select_frames.py

What it does

The model reads the brief and picks one candidate per shot need. The division of labour is fixed: the model says where the meaning lives and whether the beat and the subject are right, and the code does every piece of arithmetic. Three verdicts, not two, so a good image that is wrongly shaped or partly occluded is surfaced for review instead of silently dropped.

Failure mode

A reject rule that says "no modern product photography" lets a modern Speedmaster through anyway because the rule was not specific enough to bite. Blanket NEVER rules applied where the forbidden thing IS the subject.

Hard rule

Every NEVER names its beat. Blanket "no Kanao" rejected all 12 candidates for the need whose line is "Then he met Kanao." "no romance" rejected all 12 for the need whose line is "He fell in love with her." Both blanket rules applied where the forbidden thing WAS the subject. Every NEVER names its beat. Hard character constraints stay absolute. (EP_OBANAI rebuild, 2x re-SELECT.)

A human decision outlives the machine. A rejection made by eye is recorded in overrides.json and is read on the next run, so re-judging the batch does not quietly undo it.

Inputs: brief.json, candidates   Output: one verdict per shot need

Stage 6, Crop

Inputs

The accepted candidate per shot need, with the model's normalised safe_crop_box.

Script

crop_frames.py

What it does

Turns each accepted candidate into a 1080x1920 frame. The crop is the largest 9:16 rectangle that fits inside the source and contains the safe box, centred on the safe box and clamped to the image. Frames are deduplicated by content hash across needs, not by filename, because the same picture arrives under different names in different need folders.

Failure mode

A need with no usable verdict is skipped, and the build fills the gap by repeating a frame it already has. The episode still renders, so the loss is invisible unless something checks it.

Hard rule

A lost crop is flagged, not silent. When the safe box is wider than 9:16 the rectangle cannot contain it, so the crop keeps the safe box's centre and accepts the loss, and the frame is marked so the loss is visible rather than silent.

Inputs: verdicts   Output: frames/, the 1080x1920 masters the build draws from

Stage 7, Verify

Inputs

The verdicts, the brief, the cropped frames and the shot list.

Scripts

gate_frames.py, episode_shot_gate.py, rotcheck.py

What it does

Three checks, and each one can stop the build. The coverage pass runs after selection and refuses an episode where a shot need has no usable candidate in its own verdicts. The provenance pass runs after cropping and refuses a frame that does not come from its need's accepted candidate, a frame that shares a source picture with another frame, or a frame count that does not cover the needs. The shot gate reads the shot list and refuses a shot longer than 3.5 seconds, exactly 3.5 passes, and explicit card shots are excluded because they are meant to sit still.

Failure mode

The GOJO episode built and looked finished. It was not. The selector wrote verdicts for only 3 of 16 needs, the cropper skipped every need it had no usable candidate for and carried on, and the build cycled those 3 stills across 16 shots. Frame 06 was the wrong character. Nothing in the pipeline noticed. A human looking at the frames noticed.

Hard rule

A gate that lives in a document is a warning. A gate that lives in the driver is a gate. These checks run inside the build, they return a failure code, and the driver stops on it. A false positive is fixed by a human decision in gate_accepted.json, a file no tool rewrites.

Inputs: verdicts, brief.json, frames/   Output: pass or a refusal

Stage 8, Build

Inputs

frames/, shots.json, the narration (voice.wav), the brief.

Scripts

build_episode.py, align_words_to_script.py, caption_sync_gate.py

What it does

Cuts the episode to the narration, burns the captions in, lays the music bed, and writes the mp4. The caption alignment gate refuses a caption track that does not match the spoken words, so a silent caption change cannot ship.

Failure mode

The picture ran ahead of the caption. The beat file carries only the spoken span of each line, so 7.72s of pauses sat between the beats of a 40.02s narration. The shot list was built from the beats alone, spanned 32.30s, and the builder rescaled every shot by 1.2391 to fit the audio. At 25.6s the caption read "130 DECIBELS" over a hot-fire test that belongs to the next line, and the pictures were 7.7s out of place by the end.

Hard rule

Anchor every shot boundary to the words. A shot may get shorter only down to where the next line starts, and longer only up to where its own line ends. The opening ramp is floored at the next line for the same reason. (Measured on the Speedmaster episode, fixed in the planner and the builder, then verified on all 23 shots.)

Inputs: frames/, shots.json, audio   Output: the finished mp4

Stage 9, Post

Inputs

The finished mp4, the channel copy, the thumbnail and the pinned comment.

Script

scripts/posting/post.py

What it does

Queues the video and its copy for the channel, writes the posted record, and keeps the channel's own tracking file up to date so a title cannot be posted twice. The posting layer takes a lease before it publishes, so a scheduled run and a manual run cannot both claim the same episode.

Failure mode

Caption claims that are unsourced. A caption that asserts "Musashi arrived late and that upset his opponent" passes review because it sounds plausible, but the source says he arrived late to unbalance his opponent's composure: different mechanism, different cause, same conclusion.

Hard rule

Every claim matches the source verbatim. Two claims were cut from the Musashi caption for being unsourced, and one claim was added to the Speedmaster caption because it WAS sourced (three brands officially considered: Rolex, Longines-Wittnauer and Omega). The verification record is in the channel's POSTING_VERIFICATION.md.

Inputs: the finished mp4, channel copy   Output: a queued post and its record

The gate on the finished file

The gates above judge the project files. The last gate judges the rendered video, because a still cannot show the cut rhythm, the framing or the pacing of a shot. It makes one vision model call, and the other four checks are free.

CheckWhat it refuses
AudioTrailing silence over 3.5s before the card, a total duration out of step with the voice track, a missing music bed
Caption trackPhonetic corruptions, subtitles that stop before the last line, a frame repeated in sequence
On-screen captionsA correct caption track on a video with no burned-in captions, caught by reading the caption band out of the rendered pixels
VisualA shot whose subject, beat or framing contradicts the brief or the never-list
Frame loopDuplicate frame sequences that make the episode loop

When the gate fails, the driver does not publish and it does not give up. It parses the failure, rejects the source frame behind that shot, re-sources it, and rebuilds, for up to five iterations, and every iteration is written to a file next to the episode.

The six hard-won rules, summarised

1
Narrate first, then write the brief. The brief is written AGAINST the audio (the beats.json), not before. Estimate N beats, hand-write N t values, the TTS pauses somewhere you did not predict. The builder reads the audio, not the brief. Tengen 2: brief 19, audio 21. Tengen 3: brief 19, audio 17.
2
Five queries per need, character name first, plus a per-need verb. Identical queries put the same 50 jpgs in every folder. The selector dedups globally, so needs 7-16 silently get nothing and the build cycles a few stills. EP_GOJO rebuild cost ~$1.50 before this rule.
3
Every NEVER names its beat. Blanket rules like "no Kanao" or "no romance" rejected the wrong needs (the need where Kanao IS the subject, the need where romance IS the subject). Hard character constraints stay absolute, but the constraint is named per-beat, not globally. EP_OBANAI rebuild cost 2x re-SELECTs.
4
UNPARSEABLE response means TRANSPORT, not model failure. 361 bytes of raw response = gateway diagnostics, no model output. select_frames.py discards stderr so a timeout reads as a model fault. Fix: ask.py timeout 120s → 420s with 3-attempt backoff; MAX_CANDS 12 → 8. Cost: 4 hours of debugging on 2026-10-22.
5
Pixel review must be at full 1080x1920. Six frames passed the selector at 640px and failed human review at full resolution: watermark plate, second character, English speech bubbles, two pre-injury combat poses, and one frame with Tengen missing entirely. Confirm any "wrong character" call by opening the source PNG. Record rejections in sourced/<EP>/overrides.json, never in vererdicts.json.
6
Every claim matches the source verbatim. Two claims were cut from the Musashi caption for being unsourced; one claim was added to the Speedmaster caption because it WAS sourced. The verification record is in POSTING_VERIFICATION.md.

What this blueprint proves to a brand

A brand evaluating this work signs off on "the video is what the brief asked for", not on the mechanism. The blueprint is the proof that the work is auditable: every claim traces to a source, every frame traces to the source image it was cropped from, every NEVER rule has a name and a beat it applies to, and every failure mode is documented with the cost it took to learn it.

The gate on a real episode is documented with its mistakes as well as its findings. The worked example is a shipping episode with its own measured defects: a picture running 7.7 seconds ahead of its captions, an apostrophe dropped by the renderer, and four wrong-era frames caught by eye.
