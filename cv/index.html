How to read this CV

Terms used in the application

The CV keeps the exact wording used for applications. The definitions below explain the engineering terms for a reader who has not worked with AI systems.

Agent
A program that can choose and call tools to complete a task, rather than returning one fixed answer.
MCP
Model Context Protocol, a standard that lets an AI application call tools through a defined interface.
RAG
Retrieval-augmented generation. The system finds relevant source text before asking a model to answer from it.
Vector search
A way of comparing records by the numerical meaning of their text, rather than only matching exact words.
Evaluation harness
A controlled test that runs a system on known inputs and applies a fixed scoring rule.
Confidence gate
A rule that sends an uncertain prediction to a person instead of forcing a decision.
Orchestration
The layer that decides what runs, when it runs, and what happens when it fails.
Append-only ledger
A record that adds new outcomes without changing earlier entries.

Selected Systems

Multi-model LLM gateway: Python, sqlite, kie.ai, OpenRouter, NVIDIA NIM

  • Problem: Every model call was a direct provider call, so there was no cache, no per-call budget, no spend ceiling, no lineage, and no way to tell a reasoning burn from a real answer.
  • Action: I built one chokepoint for every call, with a sha256 response cache keyed on model, messages and parameters, a per-call budget guard, a daily cumulative ceiling read from the ledger, and a detector that quarantines a response where completion tokens equal reasoning tokens and content is empty.
  • Result: The ledger held 33,104 calls on 10 November 2026, with token counts, endpoint and cost. The registry separates vendor facts, which are fetched and overwritten, from user facts, which are hand-kept and never overwritten by a fetch, so a scheduled catalogue sync cannot silently drop a routing decision.

Multi-agent MCP layer: MCP protocol, Python, Node.js, opencode, Claude Code

  • Problem: Each AI client on the machine had its own route to models, memory, code, the web and the browser, so every client drifted into different behaviour.
  • Action: I wired eight MCP servers into one layer, unified-log, kie-ai, code-search, claude-mem, ask, comfyui, wikipedia and browser, with six also in the global config so a chat outside the project gets the same core set. The model gateway is exposed as MCP tools, so an agent inside a chat reaches models through the same budget, cache and ledger as the command line.
  • Result: A watchdog tails the transport error log, bumps the affected server’s restart marker in both config files, and the client respawns the server, verified end to end on a SIGTERM with no human intervention.

Cron orchestration with a verification ledger: bash, Python, JSONL ledger, systemd

  • Problem: 18 scheduled jobs were failing silently. A job that fires and fails and a job that never fires leave identical evidence in a log file.
  • Action: I routed every crontab line through one runner with a job name argument and made the orchestrator compare the job registry against an append-only ledger, writing an explicit per-run outcome so the two failure modes are distinguishable. The orchestrator self-heals the one repairable drift, and notifications fire only on a state change, because a monitor that reports a known-bad state every fifteen minutes trains the reader to ignore it.
  • Result: 18 jobs under one registry and 3,284 ledger records, with the exit code visible to anything watching it, 0 healthy and 1 not.

Smart Medical Records Engine: FastAPI, PostgreSQL with pgvector, Docker Compose

  • Problem: A doctor has ten minutes and a patient history spread across years of notes, and the one critical line, a past reaction to a medicine, gets missed.
  • Action: I built a clinical assistant that answers plain English questions from that patient’s own records, with retrieval scoped per patient so no other patient’s notes can surface, plus physician authorization, PII redaction, and an audit log of every access. Thirty adversarial probes tried to pull another patient’s note and none got through.
  • Result: I ran the whole stack, the API, PostgreSQL with 768 dimensional vector search and a self hosted Llama 3.1, across four Docker Compose services, so patient data never leaves the hospital’s own network.
